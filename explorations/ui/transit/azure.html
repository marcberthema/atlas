Azure

What an Azure service provides, what it requires, how it relates to other services, and how to build it with Terraform. Tiers 0 and 1 for now.

No service matches “”. to see every service.

Always there

Exists in every tenant or subscription; you don't create or enable it.

Organization

  • Entra tenant

    The identity boundary that everything in Azure hangs from.

    FreeTerraform listedNot ratedunconfirmed
    • A tenant is the directory that holds the identities used to sign in and get access. Every Azure subscription trusts exactly one tenant and relies on it to authenticate and authorize users, services and devices.
    • The person who creates a tenant becomes Global Administrator. A subscription owner who joins their subscription to an existing tenant does not.
    • Moving a subscription to another tenant breaks role assignments, so AKS clusters lose functionality, and key vault tenant IDs must be changed.

    how-subscriptions-associated-directory (2026-06-19)licensing (2026-06-18)how-to-find-tenant (2025-01-14)

  • Management groups

    Group subscriptions so policy and access apply to all of them.

    FreeTerraform fullNot ratedunconfirmed
    • Governance conditions applied to a management group cascade to all nested management groups, subscriptions and resources. All subscriptions in one management group must trust the same tenant.
    • Each directory has one root management group, named 'Tenant root group' by default, with an ID equal to the tenant ID. It can't be moved or deleted, and new subscriptions land in it by default.
    • No one has access to the root management group by default; a Global Administrator must elevate access first.
    • A directory supports 10,000 management groups and a tree up to six levels deep (not counting the root or the subscription level).

    overview (2024-07-18)

  • Azure Resource Manager

    The control plane every tool (portal, CLI, Terraform) talks to.

    FreeTerraform fullNot ratedunconfirmed
    • Every create, update or delete goes through ARM, whichever tool you use. You don't enable it; it is part of the platform.
    • ARM checks RBAC on every request and evaluates Azure Policy when one is assigned. Role and policy assignments are themselves ARM resources.
    • Resource providers (Microsoft.Compute, Microsoft.Network, ...) must be registered on a subscription before you use them. Some are registered by default, and the portal and template or Bicep deployments often register them for you. Registering needs the /register/action permission, which Contributor and Owner have.
    • Terraform's azurerm provider calls ARM's REST API resource by resource and keeps its own state file. It does not generate ARM templates.
    • Bicep is an Azure-only language that compiles to an ARM template (JSON), which ARM's deployment engine applies. No state file: Azure itself is the record. Preview changes with what-if.
    • Both describe desired state, but a deployment is one-shot: nothing keeps reconciling afterward (unlike a Kubernetes controller). Drift is found by re-running plan or what-if, or corrected by Azure Policy effects such as DeployIfNotExists.

Identity and security

  • Entra ID

    Users, groups, applications and sign-in.

    Free tierTerraform listedNot ratedunconfirmed
    • Entra ID is the foundational product of the wider Microsoft Entra family. Every tenant is automatically an Entra tenant, so Microsoft 365, Azure and Dynamics 365 subscribers already use it.
    • It is a cloud identity and access management service: authentication, policy enforcement and protection for users, devices, apps and resources.

    whatis (2026-06-18)licensing (2026-06-18)

  • Azure RBAC role assignments

    Grant a role to an identity at a given scope.

    FreeTerraform fullNot ratedunconfirmed
    • Three parts: who (principal), what (role), where (scope). Scopes inherit downward.
    • Contributor manages resources but is not a data role. Use data roles such as Key Vault Secrets User for secrets.
    • RBAC answers 'who may do what?'. Azure Policy mainly answers 'what is allowed to exist, and how must it be configured?', though policy rules can also look at who makes a request. Full RBAC access does not bypass policy.
    • A role assignment is its own ARM resource, stored at a scope, so one group assignment can cover many resources. That is why RBAC scales better than per-resource lists.
    • RBAC is additive: effective permissions are the sum of all assignments that apply. If a deny assignment applies, access is blocked before role assignments are considered.

    Core

    The services most workloads are built from.

    Organization

    • Subscriptions

      The billing, quota and access boundary for resources.

      FreeTerraform fullNot ratedunconfirmed
      • A unit of management, billing and scale, and a boundary for quota, governance, security and identity controls.
      • Trusts exactly one tenant.
      • Not tied to a region: one subscription can hold resources from many regions, and resource groups can organise them by region.

      how-subscriptions-associated-directory (2026-06-19)resource-org-subscriptions (2025-12-19)

    • Resource groups

      A container for resources that share a lifecycle.

      FreeTerraform fullNot ratedunconfirmed
      • A resource belongs to exactly one resource group.
      • Deleting a resource group deletes everything in it.
      • Resources can reference others in different resource groups.
      • A resource group stores metadata about its resources. Its location is only where that metadata is stored; resources inside can be in other regions.
      • Locks (read-only or delete) can protect a resource group from accidental deletion or change.

      manage-resource-groups-portal (2026-02-27)

    Identity and security

    • Managed identities

      Identities for Azure resources whose credentials Azure manages for you.

      FreeTerraform fullNot ratedunconfirmed
      • System-assigned: created with one resource and deleted with it. User-assigned: a standalone resource that can be assigned to many resources. Microsoft recommends user-assigned for Microsoft services.
      • You don't manage credentials, and they aren't accessible to you; code gets a token from Entra ID through MSAL or the Azure.Identity SDK.
      • Each managed identity is a special service principal in Entra ID. It has no access until you grant permissions, for example with Azure RBAC role assignments.

      licensing (2026-06-18)overview (2025-08-19)

    • Key Vault

      Store secrets, keys and certificates with access control.

      PaidTerraform fullNot ratedunconfirmed
      • Each vault uses one permission model: Azure RBAC (the default and recommended model, and the default for new vaults from API version 2026-02-01) or vault access policies (legacy).
      • Access policies exist only at the vault level. RBAC roles can be assigned at management group, subscription, resource group, vault, or an individual key, secret or certificate. One vault per application per environment, with roles at vault scope, is recommended over per-object assignments.
      • Contributor is a management role, but in access-policy mode Contributor and Key Vault Contributor can grant themselves data access by editing an access policy. Read secrets with an RBAC data role such as Key Vault Secrets User, and limit who holds Contributor.
      • Setting the RBAC permission model invalidates all access policies and can cause outages if equivalent roles are not assigned. Create the role assignments first, then switch and test.

      Free tierTerraform fullNot ratedunconfirmed

      • Workload protection is enabled as separate plans per resource type, such as Defender for Storage, SQL, Key Vault and containers.
      • Parts of Defender for Cloud are moving into the Defender portal; check which portal an article applies to.

    Governance and management

    • Azure Policy

      Enforce and audit rules on resources.

      FreeTerraform fullNot ratedunconfirmed
      • Rules about resource properties and actions. Examples: allowed regions, required tags, diagnostic logs sent to Log Analytics. Rules can also check who makes the request, so policy is not only about configuration.
      • Assigned at a management group, subscription, resource group or individual resource, and inherited downward; specific scopes can be excluded. It only applies to the resource types and properties its rule matches.
      • Evaluated when a resource is created or updated, when a policy is newly assigned or changed at a scope, and on a compliance cycle every 24 hours. Effects set the response: deny, log, alter the resource before or after the change, deploy related resources, or block actions. Existing non-compliant resources are not deleted; remediation can fix them.
      • If a Terraform apply fails with RequestDisallowedByPolicy, read the policy name in the error before debugging the code.

      Compute and containers

      • Virtual Machines

        General-purpose virtual servers you manage.

        Free for 12 monthsTerraform fullNot cloud nativeunconfirmed
        • Hard requirements: a resource group, one NIC (which needs a subnet) and an OS disk.
        • Optional: data disks, public IP, NSG, managed identity, extensions, load balancer membership.
        • GPU is not a separate resource; it comes from the VM size (N-series). The size sets vCPU, memory and GPU.
        • You still maintain the VM: configuring, patching and running the software on it.
        • Keep data on a separate disk from the OS disk, so you can detach it and attach it to a new VM if the VM fails.

        overview (2025-03-27)

      • Managed Disks

        Block storage attached to VMs.

        PaidTerraform fullNot ratedunconfirmed
        • Block-level storage volumes managed by Azure. There are five types: Ultra Disk, Premium SSD v2, Premium SSD, Standard SSD and Standard HDD.
        • A disk is a separate resource: you can detach a data disk from one VM and attach it to another.
        • You don't manage a storage account for managed disks; Azure handles it in the background.
        • Backup options include built-in redundancy (LRS and ZRS), Azure Backup, snapshots and restore points.

        managed-disks-overview (2026-08-20)

      • Virtual Machine Scale Sets

        Groups of load-balanced VM instances that scale out and in automatically.

        Service free, resources notTerraform fullNot cloud nativeunconfirmed
        • Instance count can grow or shrink with demand or a schedule, and VMs are spread across availability zones or fault domains.
        • Two orchestration modes: Flexible (the unified VM experience) and Uniform.
        • Works with Azure Load Balancer for layer 4 and Application Gateway for layer 7 traffic.

        overview (2026-05-19)

      • App Service

        Managed hosting for web apps and APIs.

        Free tierTerraform fullPartlyunconfirmed
        • Runs web apps, mobile back ends and REST APIs on a managed platform. Stacks: .NET, Java, Node.js, Python and PHP, on Windows and Linux, or any container as a custom container.
        • Virtual Network integration secures ingress and egress; App Service environments give full isolation with dedicated networking and VMs.

        • Durable Functions chain functions into event-driven workflows.

        Serverless containers that can scale to zero.

        Free tierTerraform fullCloud nativeunconfirmed
        • Serverless platform for containers: you don't manage servers or orchestrate containers yourself. Autoscaling uses any KEDA-supported scaler, and most apps can scale to zero.
        • Runs containers from any registry, public or private. Dapr is built in for microservices, and you can provide an existing virtual network when creating the environment.

      • Azure Kubernetes Service (AKS)

        Managed Kubernetes: Azure runs the control plane; Standard gives you the node pools, Automatic manages nodes too.

        Service free, resources notTerraform fullCloud nativeunconfirmed
        • Azure creates and manages the control plane for you at no cost. AKS is CNCF-certified.
        • Two modes: Automatic (fully managed, production-ready defaults, Azure handles nodes, scaling, security, monitoring and upgrades; recommended for most teams) and Standard (full control of cluster configuration and node pools).
        • In Automatic, Managed Prometheus, Container Insights and Azure Monitor dashboards with Grafana are on by default.

      Networking

      • Virtual Network and subnets

        Your private network in Azure: resources communicate with each other, the internet and on-premises networks.

        FreeTerraform fullNot ratedunconfirmed
        • Subnets are child resources of the virtual network.
        • DHCP is built in: you choose address ranges and Azure assigns private IPs to NICs.
        • DNS is Azure-provided by default, or custom servers, or private zones linked to the VNet.
        • Filter traffic between subnets with network security groups and application security groups; override Azure's default routes with route tables.
        • Virtual networks and subnets span all availability zones in a region. Peering connects virtual networks, and service endpoints extend the network's private address space and identity to Azure services.

        virtual-networks-overview (2025-07-17)

      • Network Interface (NIC)

        Lets a VM communicate with the internet, Azure and on-premises resources.

        FreeTerraform fullNot ratedunconfirmed
        • Always in exactly one subnet. You pick the subnet when you create it and can change it afterwards.
        • Holds the private IP; can also hold a public IP, an NSG and load balancer membership.

        virtual-network-network-interface (2025-07-28)

      • Network Security Group

        Allow and deny rules that filter network traffic between Azure resources in a virtual network.

        FreeTerraform fullNot ratedunconfirmed
        • Rules have a priority from 100 to 4096; lower numbers run first and processing stops at the first match. Azure's default rules have the lowest priority, so your rules always run first.
        • A rule matches on source, destination, port, protocol and direction. Sources and destinations can be an IP, a CIDR block, a service tag or an application security group.

        network-security-groups-overview (2025-07-15)

      • Public IP address

        An internet-facing address that lets resources communicate with the internet.

        PaidTerraform fullNot ratedunconfirmed
        • A resource without a public IP can still go outbound: Azure assigns an available dynamic address that isn't dedicated to you.
        • Basic SKU public IPs were retired on September 30, 2025; use Standard SKU. For scale sets, use public IP prefixes.

        public-ip-addresses (2025-02-04)

      • Load Balancer

        Layer 4 (TCP and UDP) traffic distribution across VMs and scale sets.

        PaidTerraform fullNot ratedunconfirmed
        • Public load balancers handle internet-facing inbound and outbound traffic; internal ones balance private traffic inside a virtual network.
        • Current SKUs are Standard and Gateway. Basic Load Balancer was retired on September 30, 2025.

        load-balancer-overview (2026-07-07)skus (2024-06-27)

      • Application Gateway / Front Door

        Layer 7 web traffic routing. Application Gateway is regional; Front Door is a global content delivery network.

        PaidTerraform fullNot ratedunconfirmed
        • Application Gateway works at OSI layer 7: TLS termination, autoscaling, zone redundancy and an optional Web Application Firewall. Use v2; the v1 SKUs retired on April 28, 2026.
        • Front Door is a global CDN for fast, secure access to web content and APIs. Traffic Manager is the DNS-based alternative when you don't need layer 7 processing.

        overview (2026-09-10)front-door-overview (2026-08-28)

      • Azure DNS and Private DNS

        DNS hosting and name resolution for public domains and private virtual networks.

        PaidTerraform fullNot ratedunconfirmed
        • Public DNS hosts internet-facing domains. Private DNS resolves names inside virtual networks without a custom DNS server.
        • DNS Private Resolver lets on-premises and Azure query each other's private zones without VM-based DNS servers. Traffic Manager is a separate DNS-based load balancer.

        dns-overview (2026-07-28)private-dns-overview (2025-12-16)

      • Private Endpoint

        A network interface with a private IP in your virtual network that connects privately to a service powered by Private Link.

        PaidTerraform fullNot ratedunconfirmed
        • Creates a NIC with a private IP in your subnet.
        • Needs a private DNS zone so the service name resolves to that IP.
        • Connections are approved automatically or manually depending on your RBAC permissions on the target; a manual one stays Pending until the resource owner approves.

        private-endpoint-overview (2026-08-11)

      Storage and databases

      • Storage account

        Blob, Files, Queue and Table storage under one account.

        PaidTerraform fullNot ratedunconfirmed
        • Contains blob containers, file shares, queues and tables.
        • Common uses: Terraform state, boot diagnostics, Functions state, logs.
        • Standard general-purpose v2 is the recommended type for most scenarios (blobs, files, queues, tables). Premium types exist for block blobs, file shares and page blobs, for high transaction rates or low latency.
        • Redundancy options include locally redundant (LRS), zone-redundant (ZRS), geo-redundant (GRS, RA-GRS) and geo-zone-redundant (GZRS, RA-GZRS); the options available depend on the account type.

        storage-account-overview (2026-07-16)storage-plan-manage-costs (2025-10-01)

      • Azure SQL

        Fully managed SQL Server databases (Azure SQL Database), including a serverless compute tier.

        Free tierTerraform fullNot ratedunconfirmed
        • Fully managed: built-in high availability and backups, and no patching or upgrading. The newest SQL Server capabilities often arrive in Azure SQL Database first.
        • Two purchasing models: vCore (choose vCores, memory and storage) and DTU (bundled compute, memory and I/O). Hyperscale is the recommended vCore service tier, scaling to 128 TB.
        • Serverless compute (vCore model) scales compute automatically with workload and bills per second. A free tier is available.

        free-offer (2026-10-30)sql-database-paas-overview (2026-10-13)

      • Azure Database for PostgreSQL

        Managed PostgreSQL (flexible server).

        Free for 12 monthsTerraform fullNot ratedunconfirmed
        • Fully managed PostgreSQL with granular control over configuration. Compute and storage are separated.
        • High availability within one availability zone or zone-redundant across zones: a warm standby with synchronous replication. Zone-redundant HA is not available in every region.
        • Private access: inside an Azure virtual network the server is reachable only through private IP addresses.

        overview (2026-01-09)

      • Cosmos DB

        Fully managed, globally distributed NoSQL and vector database with autoscale and serverless throughput.

        Free tierTerraform fullNot ratedunconfirmed
        • Turnkey global distribution with multi-region writes (99.999% SLA) and automatic failover. APIs: NoSQL, MongoDB, Apache Cassandra, Apache Gremlin and Table.
        • Throughput models include provisioned, autoscale and serverless. A lifetime free tier gives 1000 RU/s and 25 GB.
        • Integrated vector and hybrid search stores embeddings next to operational data.

      Messaging and integration

      • Service Bus

        A fully managed enterprise message broker with queues and publish-subscribe topics.

        PaidTerraform fullNot ratedunconfirmed
        • Decouples applications and services. Features: load balancing with competing consumers, topics and subscriptions, atomic transactions and message sessions for strict ordering.
        • Transactions allow once-only processing semantics: results become visible downstream only after the input message is settled.

        service-bus-messaging-overview (2026-03-13)

      • Event Grid

        A fully managed publish-subscribe service for event and message distribution, including MQTT.

        Free tierTerraform fullNot ratedunconfirmed
        • Two core features: MQTT messaging (v3.1.1 and v5) for IoT clients, and data distribution over HTTP with push and pull delivery.
        • Push delivery sends events to webhooks and Azure services; an event subscription defines the handler or destination.
