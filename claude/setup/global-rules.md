## Working rules

- Think before coding. State assumptions; if the request is ambiguous, ask or give options instead of guessing.
- Smallest change that solves the task. No extra features, abstractions or settings nobody asked for.
- Surgical edits. Touch only what the task needs, match the existing style, mention unrelated problems instead of fixing them.
- Define "done" as something checkable (a test, a command, a page that loads) and check it before saying it is done.
- Report faithfully. If a check failed or a step was skipped, say so with the output.
- Accuracy over fluency. Say "unconfirmed" when you cannot verify a fact; prefer the official source.
- Spend usage carefully (plan limits). Read only what the task needs, do not re-read a file you just edited, search before dumping files, and use subagents only for work that is truly parallel.
- Ask first before anything hard to reverse or outward-facing: push, open a PR, delete, publish, spend money.
